## 3. 云：多通道，不绑死一家

### 3.1 抽象

同步/备份只依赖三个动作：**列出、上传、下载**。谁提供这三件事不重要。

```rust
trait BlobStore {
    fn put(&self, sha: &str, bytes: &[u8]) -> Result<()>;
    fn get(&self, sha: &str) -> Result<Vec<u8>>;
    fn list(&self) -> Result<Vec<String>>;
}
```

### 3.2 可选通道

| # | 通道 | 需要什么 | 国内可用性 | 特点 | 优先级 |
|---|---|---|---|---|---|
| 1 | **本地文件夹** | 无 | — | 你自己用任何网盘客户端同步那个文件夹，我们只管读写磁盘。**最省事、最不依赖** | ⭐️ 首选 |
| 2 | **WebDAV** | 地址 + 账号 | 好（坚果云/群晖/Nextcloud） | 不装客户端，直连；坚果云有流量限额 | ⭐️⭐️ 推荐 |
| 3 | **S3 兼容** | endpoint + key | 好（R2/OSS/MinIO/B2） | 便宜、稳定、API 十年不变 | ⭐️⭐️ 推荐 |
| 4 | **局域网直连** | 同一 Wi-Fi | 好 | 最快，零流量；未来接手机用 | ⭐️ 有第二台设备再上 |
| 5 | **加密包** | 无 | — | 导出 zip 手动搬，适合应急/换机 | ✅ 兜底 |
| 6 | OneDrive (Graph) | OAuth 应用注册 | 差 | 登录流程复杂、国内不稳 | 🕐 最后再说 |

### 3.3 多通道并存

- 可以同时配置 2–3 个通道，按优先级尝试：**WebDAV → S3 → 文件夹 → 包**。
- 一个失败不影响其它，失败的项排队等下次。
- 每次备份是**增量**的：blob 按 SHA 命名，已在远端的自动跳过。

### 3.4 隐私

- 可选**端到端加密**：上传前用本地密钥加密（XChaCha20-Poly1305），远端只看到密文。
- 这样即使网盘做内容扫描、或账号被盗，也拿不到图。
- 代价：换设备要导入密钥（一串 24 词或一个文件）。

## 5. 关于"预留接口"

`stickerbox-core` 目前：

- 不 `use` 任何 `tauri`、`windows`、`android` 相关 crate；
- 路径全部用 `Path`/`PathBuf` 传入，不假设盘符；
- 排序、搜索、统计都在内存里，不依赖 Windows API。

将来加 Android，只需要：

1. 一个 Tauri（或 Compose）壳；
2. 两个系统接口实现：分享接收、剪贴板；
3. `core` 一行不改。

## 7. 踩过的坑：工作区内的 exe 写不了用户目录

**现象**：`cargo run` 启动即 panic，`无法打开库: 拒绝访问 (os error 5)`。

**定位过程**：

| 测试 | 结果 |
|---|---|
| bash `mkdir %USERPROFILE%\StickerBox` | ✅ 成功 |
| Python `os.makedirs(...)` | ✅ 成功 |
| 同一个 exe 从 `%TEMP%` 运行 | ✅ 成功 |
| 同一个 exe 从 `bqb\target\debug\` 运行 | ❌ 拒绝访问 |

**结论**：开发环境对「位于工作区内的可执行文件」做了路径级限制——能读工作区，不能写用户目录。和代码无关。

**修法**（已提交，`.cargo/config.toml`）：

```toml
[build]
target-dir = "C:/Users/13066/AppData/Local/StickerBoxBuild/target"
```

编译产物落到工作区外，`cargo run` 直接可用。换机器时删掉这个文件即可。

**另外还改了两处**，让程序本身更抗造：

1. 库目录按 `STICKERBOX_HOME` → `%USERPROFILE%\StickerBox` → `%LOCALAPPDATA%\StickerBox` → `./StickerBox` 依次尝试，全失败才退出，并打印每个路径的失败原因；
2. 新增 `stickerbox.exe diag`，一条命令列出所有候选目录的可写性，下次遇到权限问题不用猜。

```powershell
.\target\debug\stickerbox.exe diag
```
