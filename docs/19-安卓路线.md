# 19 · 安卓路线（Tauri，不写原生）

> 2026-10-31 · 预研结论与拆分清单

---

## 1. 结论

继续用 **Tauri 2 + Rust core + 同一套 HTML/CSS/JS**，不做 Kotlin/Compose 原生重写。

- 可复用：`crates/core`（100% 纯 Rust）、整套 UI、`index.json` 数据格式、筛选/排序逻辑；
- 需替换：`app` 里所有 Windows 专属能力；
- Kotlin 只做「系统边界」的胶水，预计 300–400 行（分享进、分享出、SAF、FileProvider）。

原生重写意味着 UI、交互、业务接口全部分叉，工作量数倍，否决。

## 2. 平台差异清单

| 桌面做法 | 安卓现实 | 方案 |
|---|---|---|
| 文件路径导入 | SAF 返回 `content://`，`std::fs` 读不了 | Kotlin 复制到 cache → Rust `import_paths` |
| 自动读剪贴板 | Android 10+ 只有前台能读 | 放弃自动捕获，用「分享到 Picarium」 |
| 复制图片粘微信 | 图片剪贴板不可靠 | 主出口 `ACTION_SEND` / `SEND_MULTIPLE` |
| 托盘 / 全局热键 / 悬浮面板 | 不存在 | 全部去掉 |
| 自定义 `thumb://` 协议 | 移动端不支持自定义协议 | asset 协议或本地 HTTP |
| hover / 右键 / 拖到侧栏 | 触摸无 hover | 长按多选、点按预览、底部分享 |
| 库放用户目录 | 分区存储 | 应用私有目录 `files/Picarium`，导出走 SAF |

## 3. 代码拆分

```
app/src/
  platform/
    mod.rs        // trait: Clipboard, RecycleBin, Hotkeys, OpenFile, ShareTarget
    desktop.rs    // 现有 Windows 实现（cfg(windows)）
    mobile.rs     // stub + 调用 Kotlin 插件
```

- Windows 模块统一 `#[cfg(windows)]`；
- Android 上禁用：单实例 TCP 端口、托盘、全局热键、剪贴板轮询、回收站、注册表自启、`ShellExecuteW`；
- 缩略图：移动端改为启动时把缩略图写进 cache，用 asset 协议读取；
- 目录：Tauri CLI 默认找 `src-tauri/`，需要把 `app/` 改名或确认 `--project-dir`（预研时定，不先动）。

## 4. 阶段

| 阶段 | 内容 | 估计 |
|---|---|---|
| M2-0 | 工具链：NDK、rust android targets、tauri-cli、`tauri android init`、模拟器空壳 | 0.5–1 天 |
| M2-1 | 平台拆分 + 桌面专属剔除 + 库/缩略图跑通 | 1–2 天 |
| M2-2 | SAF 导入 + 分享进入 | 2–3 天 |
| M2-3 | 移动端 UI + 分享出去 | 2–3 天 |
| M2-4 | 导出备份（SAF）、图标、release 签名 | 1–2 天 |

合计约 1–1.5 周（业余节奏）。

## 5. 当前环境

- 已有：Java 21、Android SDK（platform 28/35、build-tools、emulator）。
- 缺：`ANDROID_HOME`、NDK、Rust 安卓 target、Tauri CLI、仓库 `package.json`。
- 风险：依赖需联网下载；若代理不可用，M2-0 会卡住。

## 6. 风险

- Tauri 移动端插件生态仍在演进，版本要钉死；
- `content://` 复制有额外 IO，导入大图时注意进度提示；
- 低端机 WebView 性能：本次虚拟滚动是前提；
- 分享进入时 app 已启动的场景要用事件而不是重启。

## 7. 非目标（安卓 v1）

自动剪贴板捕获、托盘/热键、悬浮面板、桌面式拖拽、iOS。
