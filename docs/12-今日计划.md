## 2. 今天的主线：剪贴板捕获

### 目标

在微信/QQ/浏览器里 `Ctrl+C` 复制一张图 → 库里自动多一条 → 侧栏「未分组」红点 +1。

### 设计（已确认）

- 轮询 `GetClipboardSequenceNumber()`，250ms；
- 所有应用都收，不设白名单；
- 记录来源应用名（前台窗口进程）作为**标签**；
- 进「未分组」；
- 名字格式 `来源-月日-时分`；
- 托盘菜单加「暂停捕获」；
- 同一张图重复复制只算重复，不新增。

### 验收

1. 从微信复制一张图 → 3 秒内出现在库里；
2. 名字形如 `微信-1029-1530`；
3. 标签里能看到来源；
4. 未分组红点 +1；
5. 从本应用复制出去，不会产生新条目；
6. 暂停后复制，不入库；恢复后正常。

## 6. 修复记录（01:45）

你反馈的两个现象，根因是同一个链条：

1. 点图复制 → 我们写剪贴板（RGBA）
2. 剪贴板监听发现变化 → 读回来 → 编码成 PNG
3. PNG 的哈希和原图（JPEG）不同 → 当成新条目入库
4. 于是多出一张「一模一样但大小不同」的图

再叠加：监听线程和 UI 线程同时抢剪贴板 → `OS error 1418`（线程没有打开剪贴板）。

**修法**：

| 问题 | 处理 |
|---|---|
| 自我捕获 | 写剪贴板前开 1.5 秒抑制窗口，监听器在窗口内直接跳过 |
| 剪贴板竞争 | 全局一把锁，读和写串行化 |
| 偶发占用 | 写入失败重试 5 次（每次 60ms），仍失败才报错 |

**验证**：自测钩子复制一张 735×723 的图，库条目 18 → 18（零新增），剪贴板正常有图。

**清理**：历史自捕获产生的 5 条 `stickerbox-*` 重复已移入 `trash/`，库 18 → 13。
