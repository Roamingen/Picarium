# 浏览器插件方案（B站 → StickerBox）

> 状态：P0–P2 已落地（2026-11-10），P3 未做。只做 B 站；插件用 TypeScript；本地 HTTP 桥。
> 决策见文末「已定案」；落地细节与差异见文末「实现状态」。

## 1. 目标与范围

**MVP（第一批只做这个）**
- 在 B 站页面，把一张**动图/静态图**一键导入 StickerBox 库（GIF / WebP / PNG / JPG，动画保真）。
- 入口：右键菜单「存入 StickerBox」（最稳、代码最少）+ 后续悬浮按钮。

**明确不做（本批）**
- X / Twitter（其「GIF」是 H.264 MP4，core 不支持 mp4，见 `docs/17-平台限制.md` 与 `crates/core/src/lib.rs:20` 的 `IMAGE_EXTS`）。
- 「下载到本地文件夹」：直接进库即完成，不落中间文件。
- 多选批量、登录态接口抓取（动态流自动抓）等增强。

## 2. 总体架构

```
浏览器 (B站页面)
  └─ content script (content.ts)：找到图片 URL、注入按钮/右键菜单
        │  chrome.runtime.sendMessage({url, name})
        ▼
  background service worker (background.ts)
    1. fetch(url, {credentials:'include'})   ← 带页面 cookie 抓媒体字节（host_permissions 免 CORS）
    2. POST http://127.0.0.1:17800/import     ← JSON(base64) + X-StickerBox-Token 头
        ▼
  StickerBox 壳 (Rust, 桌面端)
    bridge.rs：std::thread + tiny_http 监听 127.0.0.1:17800
      └─ 校验 token → 解 base64 → core::import_media_bytes → ensure_thumb
        ▼
  crates/core Library（blobs/ + index.json，动画标记正确）
```

要点：
- **桥只监听 `127.0.0.1`**，不出网。
- **扩展后台 SW 直接 fetch**（不是 content script 里 fetch），content script 只负责「找 URL + 发消息」，媒体抓取集中在 background，权限清晰、好调试。

## 3. 桥接方式（已定：HTTP + token）

沿用上一轮结论：**本地 HTTP 桥 + 自定义头 token**。

- 端口：固定 `127.0.0.1:17800`（后续可进 `settings.json` 配置）。
- 鉴权：`X-StickerBox-Token` 头，值 = 固定共享密钥（个人自用，默认烘焙进两端；见待拍板点 3）。
- 为什么够安全：普通网页跨站 fetch 设不了这个自定义头（会先发 CORS 预检、且不知道 token 值），token 只在扩展和本机应用里，所以 CSRF/垃圾注入打不进来。

对比（已在上轮定案，这里只归档结论）：Native Messaging 更安全但要注册原生宿主、部署重；自定义协议 `stickerbox://` 只能传 URL、X 登录态抓不到字节；剪贴板/监控文件夹会丢 GIF 帧或需落盘——均不选。

## 4. Rust 侧改动

### 4.1 core：新增 `import_media_bytes`（关键，修 animated 坑）

现状硬伤（实测）：
- `crates/core/src/lib.rs:396` `import_image_bytes(...)` 在 `:428` 把 `animated` 写死 `false`，且宽高要调用方传入——剪贴板路径没问题（PNG 本来静态），但**桥导 GIF 会被标成静态图，点复制走位图路径丢动画**。
- 真正算动图的是 `add_file`（`:486` `looks_animated(path, ext)`，GIF 恒 true / APNG 查 acTL / 动画 WebP 查 ANIM），但它硬编码 `source: "folder"`（`:496`）、只吃文件路径。

新增原语（复用现有 `blob_path` / `image::image_dimensions` / `looks_animated`，逻辑与 `add_file` 对齐）：

```rust
/// 从内存字节入库（浏览器桥用）。自动探测宽高 + 动图标记，
/// 自定义 source/source_ref/tags，避免把 GIF 误标成静态图。
pub fn import_media_bytes(
    &mut self,
    data: Vec<u8>,
    ext: &str,
    name: &str,
    source: &str,
    source_ref: &str,
    tags: Vec<String>,
    groups: Vec<String>,
) -> Result<MediaImport>          // MediaImport { sha: String, added: bool }
```

内部：sha 去重（`seen`）→ 写 `blobs/ab/cd/<sha>.<ext>`（先 tmp 再 rename，同 `add_file:467-476`）→ `image::image_dimensions` 取宽高 → `looks_animated` 取动图 → 组 Asset（`added_at`/`py`/`readings` 照旧）→ `save()`。

> 不动 `import_image_bytes`，剪贴板路径零影响。

### 4.2 新增 `src-tauri/src/bridge.rs`

- 依赖：**新增 `tiny_http`**（纯 Rust、阻塞、无 async 运行时、体积极小；比手搓 HTTP 解析稳，能正确处理 Content-Length/keep-alive/OPTIONS）。—— 新依赖，需用户点头（待拍板点 2）。
- 线程：`std::thread::spawn`，`TcpListener::bind("127.0.0.1:17800")`。
- 入参：`lib: Arc<Mutex<Library>>`、`root: PathBuf`、`token: String`（从 `AppState` 克隆，见 `src-tauri/src/state.rs:38`）。
- 端点：
  - `GET /ping` → `200 {"ok":true,"version":"<cargo version>"}`（扩展探测应用是否在跑）。
  - `POST /import` → 校验 `X-StickerBox-Token` == token（否则 `401`）→ 解 JSON → 校验 `ext ∈ IMAGE_EXTS` → `import_media_bytes` → `ensure_thumb(&root, &sha, &ext)`（对齐 `main.rs:395`/`commands.rs:973`）→ `200`。
- 防御：处理 `OPTIONS` 预检 + `Access-Control-Allow-Origin: *` / `Allow-Headers: X-StickerBox-Token, Content-Type` / `Allow-Methods: GET, POST, OPTIONS`（虽然扩展有 host_permissions 可免 CORS，但加上更稳、便于调试）。
- 上限：body 大小上限（如 10 MB）防止把内存/库撑爆；超限 `413`。
- 生命周期：随桌面 App 启动（`main.rs` 的 `.setup` 里 `bridge::spawn(...)`），只 desktop 编译，安卓不挂（`#[cfg(not(mobile))]`）。

### 4.3 `main.rs` 接线

在 `.setup` 里拿到 `AppState`（`app.state::<AppState>()`，见 `main.rs:113`），克隆 `state.lib`、算 `root`、读 token，`bridge::spawn(...)`。端口被占则打印告警、桥失效但不影响 App 本体（不 panic）。

## 5. 扩展侧（`extension/`，TypeScript，独立 MV3 工程）

### 5.1 目录

```
extension/
  manifest.json          # MV3
  package.json           # devDeps: typescript, esbuild, @types/chrome
  tsconfig.json
  src/
    background.ts        # SW：fetch 媒体 → POST /import
    content.ts           # bilibili 页：右键菜单（MVP）/ 悬浮按钮（P2）
    lib/media.ts         # B站 CDN URL 归一化（剥 @ 后缀、判 gif/webp）
    lib/bridge.ts        # POST /import 客户端 + /ping
  dist/                  # esbuild 产物（gitignore）
```

- 构建：`esbuild`（单二进制、配置极简）把 `content.ts` 与 `background.ts` 各打成独立 JS（共享 `lib/` 模块）。命令 `npm run build`。
- **与 Tauri 零耦合**：扩展是独立工程，不进 `src-tauri` bundle，不参与 `cargo build`；Chrome「加载已解压的扩展程序」指向 `extension/dist/`。
- 说明：StickerBox 前端 `app.js` 无构建步骤是它的选择，扩展这边 TS 必然要一步 esbuild，两者互不影响。

### 5.2 manifest.json 关键项

- `manifest_version: 3`
- `background.service_worker: "background.js"`
- `permissions`: `contextMenus`, `storage`
- `host_permissions`:
  - `http://127.0.0.1:17800/*`（桥）
  - `https://*.bilibili.com/*`、`https://*.hdslb.com/*`（B站图片 CDN 抓字节）
- `content_scripts`: 匹配 `https://*.bilibili.com/*`，注入 `content.js`
- `icons` + `action`（可选，给个空 popup 或禁用）

### 5.3 background.ts（核心链路）

```
onMessage({type:'save', url, name}) →
  1. url = normalize(url)                       // lib/media.ts：剥 @ 后缀
  2. res = await fetch(url, {credentials:'include'})   // host_permissions 免 CORS
  3. bytes = await res.arrayBuffer()            // 大小上限校验
  4. ext = sniff(bytes) ?? 从 url/Content-Type 猜  // gif/webp/png/jpg
  5. POST /import {ext, name, source:'bilibili', source_ref:url, data:base64}
  6. 回传结果 → 可选 chrome.notifications 提示「已入库 / 重复 / 失败」
```

### 5.4 content.ts / 入口

- **MVP 右键菜单**：`chrome.contextMenus.create({contexts:['image'], title:'存入 StickerBox'})`；点击后 `info.srcUrl` 即图片 URL，直接走 background。不解析 DOM，最稳。
- **P2 悬浮按钮**：在 `.gif` 的 `<img>` 右上角叠角标，点击同链。DOM 较复杂（懒加载、`<picture>`、动态面板），放第二批。
- **B站 CDN 归一化**（关键）：B站图片 src 常带 `@` 处理后缀（如 `xxx.gif@320w_200h.webp`、`@!webp`），要**从第一个 `@` 截断**拿回原格式 URL，否则抓到的可能是转码 webp、甚至不是动图。

## 6. API 契约（桥）

```
GET /ping
  → 200 {"ok":true,"version":"0.12.0"}

POST /import
  Headers: X-StickerBox-Token: <token>, Content-Type: application/json
  Body: {
    "ext": "gif",                    // 小写，∈ IMAGE_EXTS
    "name": "emoji-123.gif",         // 可选；空则用 url 文件名/untitled
    "source": "bilibili",
    "source_ref": "https://i0.hdslb.com/bfs/.../xxx.gif",  // 原 URL（去 @ 后）
    "data": "<base64>"
  }
  → 200 {"ok":true,"sha":"...","added":true}   // added=false 表示库里已存在（去重）
  → 400 非法 ext / JSON 错；401 token 错/缺；413 超大小上限；500 入库异常
```

## 7. 关键坑与对策（汇总）

1. **animated 硬编码 false**（`crates/core/src/lib.rs:428`）→ 新增 `import_media_bytes` 自动探测（4.1）。
2. **B站 CDN `@` 后缀** → 剥 `@` 后缀再抓（5.4）。
3. **X 的 GIF 是 MP4** → 本批不做（1）。
4. **CORS/预检** → 扩展用 host_permissions 让 SW fetch 免 CORS；桥仍处理 OPTIONS + CORS 头兜底（4.2）。
5. **端口冲突** → 17800 被占则告警不 panic，后续可配置端口（4.2）。
6. **体积上限** → 桥 + 扩展双侧 10 MB 上限，超限 413（4.2 / 5.3）。
7. **去重** → `import_media_bytes` 内 sha 去重，重复导返回 `added:false`，扩展提示「已存在」。
8. **缩略图** → 桥 import 后 `ensure_thumb`，否则列表没缩略图（4.2）。

## 10. 实现状态（2026-11-10）

- **P0 ✅** `crates/core/src/lib.rs` 新增 `import_media_bytes` + `MediaImport` + `is_image_ext`，自动探测宽高/动图、按 sha 去重；2 条单测（core 共 22 条）。
- **P1 ✅** `src-tauri/src/bridge.rs`：tiny_http 监听 `127.0.0.1:17800`，固定 token、`GET /ping`、`POST /import`、OPTIONS/CORS、10 MB 上限；`main.rs` 的 `.setup` 起线程，端口被占只告警。2 条桥单测（`cargo test -p stickerbox --lib bridge::`）。
- **P2 ✅** `extension/`：MV3 + TypeScript + esbuild；右键菜单在 background 里创建，点击后抓字节 → 嗅探格式 → POST 桥。构建产物 `extension/dist/`（已含 manifest），Chrome「加载已解压的扩展程序」选它。

与方案的差异：

- token 固定值 `stickerbox-local-7f3c9a2e`：Rust 在 `bridge.rs::TOKEN`，扩展在 `src/lib/bridge.ts::TOKEN`。调试时可用 `STICKERBOX_BRIDGE_TOKEN` 覆盖 Rust 侧（扩展侧要同步改并重新构建）。
- `GET /ping` 不校验 token（只回版本号，方便扩展探测应用在不在）；只有 `POST /import` 校验。
- P2 没有加 content script：右键菜单是浏览器级 API（`contextMenus` 只在扩展上下文可用），MVP 不需要页面脚本；P3 做悬浮按钮时再加 `content.ts`。
- 失败提示先用扩展图标角标（✓ / = / !）+ 悬停 title + console，没申请 `notifications` 权限；P3 再做更显眼的提示。
- 右键菜单用 `documentUrlPatterns: ["https://*.bilibili.com/*"]` 限定在 B 站页面：扩展只有 B 站 + hdslb 的 host 权限，在别的站点显示菜单点了也抓不到图。以后要泛化，得同时把域名加进 `host_permissions` 并让 `source` 跟着站点走。
- 导入完成后桥向主窗发两个事件：新图发 `library-changed`（复用剪贴板捕获的刷新通道），新旧都发 `bridge-imported`；前端据此实时重拉列表并 toast「已存入 StickerBox」/「这张已经在库里了」。窗口隐藏时事件照常刷新，下次打开看到的就是最新列表。
