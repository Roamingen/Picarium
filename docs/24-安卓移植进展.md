### 6.2 坑：安卓 WebView 里「内部滚动容器」会画错

现象：把网格放进 `overflow-y:auto` 的容器（并且 `-webkit-overflow-scrolling:touch`），
模拟器上整片网格被画成 25px 一条的彩色条纹，但 `getBoundingClientRect()` 量出来每张卡是 118×118。
`adb screencap` 和 CDP 截图一致 → 不是截图工具的问题，是合成器真的画错。

结论/做法：**移动端不用内部滚动容器**，改成整页（body）滚动：

- `.app` 用 `min-height:100dvh`，不设固定高度；
- 顶栏 + 搜索 + 分类 chips 放进 `.topwrap`，`position:sticky; top:0`；
- 底部导航和 FAB 用 `position:fixed`；
- 网格 `.grid` 不再设 `overflow`。

### 6.3 坑：WebView 可能比 Rust `setup` 先跑

移动端页面启动时会先发 `list_assets`，而 `AppState` 是在 `lib.rs` 的 `setup` 里 `manage` 的，
偶发报 `state not managed for field state on command list_assets`。
`mobile.js` 里用 `invokeRetry()` 对这类错误重试（最多 ~3 秒），其余错误照常抛出。
根治方向：以后把图库打开提前到 Builder 之前，或加一个 `app_ready` 命令让前端等。

## 7. 批 6：分组页 + 封面 + 置顶

### 7.1 数据模型（`index.json` 新增，老库自动兼容）

| 字段 | 含义 |
|---|---|
| `group_order` | 分组顺序（给后面的拖拽排序用；缺省按名字排） |
| `group_covers` | 分组名 → 组内一张图的 sha |
| `pinned_groups` | 置顶分组（按置顶顺序） |

三个字段都带 `#[serde(default)]`。老库打开时自动规范化：顺序表里缺的分组补到末尾；
封面只保留「图还在、而且确实在这个组里」的记录；置顶过滤掉不存在的分组。

桌面端 `group_stats` 仍按数量倒序（侧栏暂未改），新命令 `group_list` 返回带顺序 / 封面 / 置顶的列表。

### 7.2 命令（lib crate，桌面 + 安卓共用）

新增 `group_list / set_group_cover / set_group_order / set_pinned_groups`；
并把 `create_group / rename_group / remove_group` 从 `main.rs` 迁进 `commands.rs`，两端 handler 都注册。

### 7.3 手机端

- 分组页：两列封面文件夹、分组搜索、右上「+」新建；长按卡片 → 换封面 / 重命名 / 置顶 / 删除（只解散，不删图）。
- 点分组 → 分组详情：顶部返回 + 换封面，网格和图库一致，0 张的分组也有空状态。
- 图库置顶条：读 `pinned_groups`（没置顶时退回分组顺序前 4 个），有封面就显示封面；
  超过 4 个才出现「展开 / 收起」；点置顶分组 = 切到分组 tab 并打开该组（不再切成图库筛选）。
- 封面走共享的 `thumb://`；GIF 封面直接请求原文件（`?raw=1`），所以分组页和置顶条上的动图封面会动，静态图仍用缩略图。
