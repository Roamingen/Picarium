### 6.2 坑：安卓 WebView 里「内部滚动容器」会画错

现象：把网格放进 `overflow-y:auto` 的容器（并且 `-webkit-overflow-scrolling:touch`），
模拟器上整片网格被画成 25px 一条的彩色条纹，但 `getBoundingClientRect()` 量出来每张卡是 118×118。
`adb screencap` 和 CDP 截图一致 → 不是截图工具的问题，是合成器真的画错。

结论/做法：**移动端不用内部滚动容器**，改成整页（body）滚动：

- `.app` 用 `min-height:100dvh`，不设固定高度；
- 顶栏 + 搜索 + 分类 chips 放进 `.topwrap`，`position:sticky; top:0`；
- 底部导航和 FAB 用 `position:fixed`；
- 网格 `.grid` 不再设 `overflow`。

### 6.3 坑：WebView 可能比 Rust `setup` 先跑

移动端页面启动时会先发 `list_assets`，而 `AppState` 是在 `lib.rs` 的 `setup` 里 `manage` 的，
偶发报 `state not managed for field state on command list_assets`。
`mobile.js` 里用 `invokeRetry()` 对这类错误重试（最多 ~3 秒），其余错误照常抛出。
根治方向：以后把图库打开提前到 Builder 之前，或加一个 `app_ready` 命令让前端等。

## 11. 批 10：分享出 + 存相册

### 11.1 分享出（用户选图 → 系统分享面板）

- 前端：预览页「分享」、多选条「分享」都调 `invoke("share_assets", { shas })`。
- `src-tauri/src/commands.rs` 的 `share_assets`：从库里按 sha 取 `Asset.path`；桌面端仍走 `platform::desktop::platform().share_paths`（复制路径），Android 端走 `platform::android::Android::share_paths`。
- Java 桥 `src-tauri/gen/android/app/src/main/java/dev/stickerbox/desktop/ShareBridge.java`：
  - `shareFiles(Context, String[], String mime)`：把每个文件先拷到 `context.getCacheDir()/share/`（库根在 `/data/data/<pkg>/StickerBox`，不在 `files/` 下，FileProvider 的 `files-path` 覆盖不到），再用 `FileProvider.getUriForFile(context, packageName+".fileprovider", dst)` 取 content:// URI。
  - 单张 `ACTION_SEND`、多张 `ACTION_SEND_MULTIPLE`，带 `FLAG_GRANT_READ_URI_PERMISSION`，外面套 `Intent.createChooser(..., "分享到")` 并给 chooser 加 `FLAG_ACTIVITY_NEW_TASK`（Application context 起 Activity 必须）。
- Rust 侧 JNI：`platform/android.rs` 的 `with_activity()` 用 `ndk_context::android_context()` + `JavaVM::attach_current_thread()`；Java 抛异常时 `exception_describe` + `exception_clear` 转成 `Err`。

### 11.2 存相册

- 预览「存相册」调 `invoke("save_to_gallery", { sha })`。
- `ShareBridge.saveToGallery(Context, path, name, mime)`：写 `MediaStore.Images.Media.EXTERNAL_CONTENT_URI`；Android 10+ 用 `RELATIVE_PATH = Pictures/StickerBox` + `IS_PENDING=1/0`，不需要存储权限；8/9 走默认路径（需 `WRITE_EXTERNAL_STORAGE`，暂未声明）。
- 返回后前端 toast「已存到相册 Pictures/StickerBox」。

### 11.3 三个坑

1. **Application 不是 Activity**：`ndk_context` 暴露的 `context()` 是 `android.app.Application`，Java 方法参数写成 `Activity` 时 CheckJNI 直接 abort：`JNI ERROR (app bug): attempt to pass an instance of android.app.Application as argument 1 to ... saveToGallery(android.app.Activity, ...)` → 参数与 JNI 描述符统一改成 `android.content.Context`。
2. **FileProvider 覆盖不到库根**：库在 `/data/data/<pkg>/StickerBox/…`，`<files-path>` 只映射 `<pkg>/files/…`，`getUriForFile` 抛 `IllegalArgumentException: Failed to find configured root that contains ...` → 分享前把文件拷到 `cache/share/`，FileProvider 的 `<cache-path path=".">` 已覆盖缓存目录。
3. **toast 被预览盖住**：`.toast` z-index 20 < `.viewer` 40 → 「已存到相册」看不到；提到 90。

## 11. 相册导入 + 分享收件箱（2026-10-31）

### 11.1 从手机相册导入

- 入口：「我的 → 从手机相册导入」。
- 实现：自建 JNI 桥 `PickerBridge.java`（`ACTION_PICK_IMAGES`，Android 13+，最多 100 张；旧系统回退 `ACTION_OPEN_DOCUMENT`）。
  Activity result 后把 URI 流拷进 `cache/import/`，Rust `pick_gallery_images` 取回本地路径，再走 `import_paths_simple` 入库。
- **扩展名要嗅探文件头**：相册/分享给的 `content://` URI 往往不带扩展名，按 URI 猜会把 PNG 存成 `.jpg`，
  缩略图解码失败（表现为网格里空白卡）。新增 `MediaCopy.java`：先拷到 `.tmp`，读前 12 字节判断 png/gif/webp/jpeg，再改名。
  `PickerBridge` 与 `InboxBridge` 都改用它。

### 11.2 分享到 StickerBox（收件箱）

- `AndroidManifest.xml` 的 MainActivity 增加 `ACTION_SEND` / `ACTION_SEND_MULTIPLE` + `image/*` intent-filter。
- `MainActivity.kt` 在 `onCreate` 与 `onNewIntent` 调 `InboxBridge.capture(intent)`：
  取 `EXTRA_STREAM`（或 ClipData），拷进 `cache/inbox/`，存在静态列表里；Rust `takePaths()` 取走并清空。
- Rust：`ShareTarget::take_shared`（android）→ 命令 `take_shared_paths`；桌面返回空。
- 前端：启动时与窗口重新获得焦点（`focus` / `visibilitychange`）时调 `take_shared_paths`，
  有内容就在图库顶部显示横幅「收到 N 张图片 / 导入 / 忽略」；未导入时「我的 → 分享收件箱」显示「N 张待整理」。
- 导入复用 `import_paths_simple`，按 sha 去重（重复时提示「已导入 0 张（N 张已存在）」）。
