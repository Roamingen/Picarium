## 6. 已知坑（会重复踩的）

1. **本机 pwsh 跑原生命令进管道必挂**：`ResourceUnavailable: Program 'cargo.exe' failed to run: 拒绝访问`。验收走 `.demo/verify-search.sh`（或 `verify-a.sh`），别用 `accept.ps1`。
2. **`cargo` target-dir 在工作区外**（`.cargo/config.toml` → `C:/Users/13066/AppData/Local/StickerBoxBuild/target`），workspace-write 沙箱会 `os error 5`；需要 danger-full-access。
3. **前端资源编进二进制**：改 `app.js` / `style.css` / `mobile.js` / `mobile.html` 后必须 `cargo build -p stickerbox`，不然跑的是旧界面。
4. **构建前先杀进程**：`stickerbox.exe` 还在跑时 `cargo build` 返回 101 + `拒绝访问。 (os error 5)`；`taskkill //F //IM stickerbox.exe` 再构建（release.ps1 自己会 Stop-Process）。
5. **隐藏窗口 CDP 只出白帧**：`--tray` 隐藏时 WebView2 不绘制；截图要「屏幕外无激活显示」。窗口枚举须 `CharSet.Unicode` + `class=="Tauri Window"`。
6. **`.tools/` 被 `.gitignore:20` 忽略**，新增脚本要 `git add -f`；`.demo/` 整体 gitignore，测试脚本不进库。
7. **函数重名静默覆盖**：`app.js:4012` 有老 `startCapture`；新增全局函数前先 grep。
8. **回收站不能用虚拟滚动**：`loadTrash()` 里移除 `.virtual`，否则重建会把角标/EVA 框吃掉。
9. **手机端只有静态 harness**：`.demo/mh/` 用 `__TAURI__` stub，能验 CSS/文案/交互，验不了真机 WebView/命令链路；真机验收等下次 release 一起做。
10. **手机截图别用 `--window-size`**：Chrome headless 会给出 ~500 CSS 宽再裁图；必须 CDP `Emulation.setDeviceMetricsOverride(390×844, dsf=2, mobile=true)`（`shot-me.mjs` 已封装）。
11. **版本显示读 Cargo**：改了 `tauri.conf.json` 不写 `Cargo.toml`，设置页还是旧号；`release.ps1` 的 `Write-CargoVersion` 负责同步。
12. **`-BumpOnly` 必须带 `-Bump`**，否则脚本主动 throw；`Write-Version` 只用正则替换两个值，别手改 JSON 格式（会产生大 diff）。
13. **`hidden` 属性会被 `display:flex` 覆盖**：搜索行用 `[hidden]{display:none}` 兜底（PC/手机都已加）。
14. **手机搜索「分区名命中=整组显示」**：不是 bug，改严格版要对齐 mock 再动。
15. `.demo/mh/index.html` 是 11-05 的 `mobile.html` 冻结副本（只提供 `__TAURI__` stub）；改 `mobile.html` 后重新跑 `build-me.mjs` 生成 `me.html`，别直接改 `me.html`。
