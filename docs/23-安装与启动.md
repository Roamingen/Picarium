# 23 · 安装与启动（release / 静默启动）

> 2026-10-31（2026-11-19 更新安装目录）

---

## 1. 为什么之前会弹终端

- `debug` 构建是 **console 子系统**（PE subsystem = 3），Windows 会为它分配一个控制台窗口；Windows 11 默认用 Windows Terminal 承载，所以看起来是“先开了一个终端”。
- `release` 构建带 `windows_subsystem = "windows"`（PE subsystem = 2），不创建控制台。

验证：

```
debug   subsystem = 3
release subsystem = 2
```

所以不是 bug，是构建类型。日常使用请用 release。

## 2. 安装 release

```powershell
pwsh -NoProfile -File scripts/install-release.ps1
```

它会：

1. `cargo build --release -p stickerbox`；
2. 结束正在运行的旧进程；
3. 复制到 `%LOCALAPPDATA%\Picarium\Picarium.exe`；
4. 迁移桌面快捷方式、让旧 Run 键指向新目录，并清理旧安装目录；
5. 如果注册表里已有开机自启项，自动改成指向 release（保留 `--tray`）。

之后请从 `%LOCALAPPDATA%\Picarium\Picarium.exe` 启动，或重跑脚本更新。旧的 `%LOCALAPPDATA%\StickerBox` 目录若只剩安装文件会被自动删除。

## 3. 静默启动不再闪

原实现：窗口配置默认可见 → 启动后 setup 里再 `hide()`，中间会闪一下。

现在：

- `tauri.conf.json` 里主窗口 `"visible": false`；
- setup 里判断：
  - `--tray` 或 `settings.startHidden` → 保持隐藏，只留托盘；
  - 否则 `show()` + `set_focus()`。

验证方法：用 `--tray` 启动后枚举该进程的可见顶层窗口，主窗口标题始终不出现；进程保持存活。

## 4. 开发与日常分离

| 场景 | 用哪个 |
|---|---|
| 日常使用 / 开机自启 | `%LOCALAPPDATA%\Picarium\Picarium.exe` |
| 跑验收 / 看日志 | `cargo build -p stickerbox` 的 debug 版本 |

验收脚本现在用 `Start-Process -WindowStyle Hidden` 启动 debug 版，只隐藏控制台，不影响测试。
