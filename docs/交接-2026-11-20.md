## 6. 已知坑（会重复踩的）

- **`ops_edit_file` 保留源文件 mtime**：同尺寸编辑（例如 `0.14.1`→`0.15.0`）Git 可能看不到，cargo 也会误判 Fresh；改完执行 `touch` 或核对 exe 时间。不要为此再 `cargo clean`。
- **`cargo clean -p stickerbox` 删过 18.2 GiB 缓存**：之后 release 从零重编，用户看到 5 分钟构建；不是代码变大。现在缓存已热，正常增量 release 约 2m44s–3m。
- **Cargo target 在 workspace 外**：`C:/Users/13066/AppData/Local/StickerBoxBuild/target`；workspace-write 下可能报 `.cargo-lock` 拒绝访问，需要 danger-full-access。release 还要写 `%LOCALAPPDATA%\Picarium`、桌面快捷方式与 HKCU Run 键。
- **旧 exe 不能在 `release/pc` 原地回滚**：旁边若已有 `StickerBox-0.14.1.exe.WebView2`，setup 会报 `Failed to setup app: 拒绝访问 (os error 5)`；把旧 exe 复制到干净临时目录再启动。
- **`release.ps1` 只停旧 App，不自动重启**：发布后要自己隐藏启动 `%LOCALAPPDATA%\Picarium\Picarium.exe --tray`，确认桥 0.15.0 / 47821 监听。
- **Android applicationId 变更 = 新应用**：旧安装不升级，旧包私有数据不迁移；模拟器先卸载旧包，真实手机不要直接覆盖测试。
- **单实例端口 47821 / 桥端口 17800**：旧版和新版同时跑会抢端口；测试先退旧版。
- **`Start-Process -RedirectStandardError` 的日志在进程运行时可能为空**：停进程后再读；测试脚本不要先把进程对象置 null 再读它的 ErrText。
- **`taskkill` 在 MSYS bash 里要用** `MSYS2_ARG_CONV_EXCL='*' taskkill /F /PID ...`；否则 `/F` 会被路径转换。
- **`run_code` 默认 120s 超时**：release 用 `run_in_background` + `job_output wait`；超时会杀进程树。
- **`docs/11-待办.md` 有 11 行既有改动**：未提交、不要动、不要带进其它 commit；`docs/mock/icon/` 是未跟踪目录，也不要动。
- **app data 新旧两份都保留**：`dev.stickerbox.desktop` 用于回滚，确认稳定前不要删；真实库已改名，旧库路径不存在。
- **截图/APK/录屏不进 git**：截图放 `.demo/`（已忽略），用 `present` 给用户看。
