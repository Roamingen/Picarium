## 1. 问题定义

### 1.1 现状盘点

| 痛点 | 具体表现 | 严重度 |
|---|---|---|
| **相册污染** | 手机相册几千张图里混着表情包，相机胶卷、截图、表情包、保存的图片全在一屏 | 🔴 高 |
| **找图靠翻** | 聊天时要找一个「无语」的表情，得在微信表情面板里横向划十几屏，或者回相册翻 | 🔴 高 |
| **平台割裂** | 微信收藏的、QQ 收藏的、相册存的、群里存的，四个地方各有一份，互不相通 | 🔴 高 |
| **重复堆积** | 同一张表情被转发保存多次，分辨率不同、格式不同，肉眼分不清 | 🟡 中 |
| **无法分类** | 微信/QQ 的表情面板只有「最近使用」，没有标签、没有搜索、没有文件夹 | 🟡 中 |
| **迁移困难** | 换手机、重装、换号，收藏的表情基本等于清零 | 🟡 中 |
| **手机端不可控** | 非 root 的 HyperOS 读不到微信私有目录，想批量导出没有正规入口 | 🟢 低（但决定架构） |

### 1.2 量化基线（本机实测，2026-10-28）

- 微信 PC 自定义表情：**1464** 个，100 MB，全部加密
- QQ 收藏表情：**379** 个；QQ 收到过的表情缓存：**503** 个，全部明文
- 手机相册：估计 **2000–5000** 张（待你确认）

> 结论：**光是 QQ + 微信两块，就有近 1900 张存量**。这不是「偶尔用用」的小工具，是值得做好的个人资产管理系统。

### 1.3 一句话问题陈述

> 我需要一个**本地优先的表情包库**：所有来源的表情包都汇到一处，能自动分类、能秒搜、能在微信/QQ 里三秒贴出去，并且 Windows 和手机共享同一个库。

## 2. 设计原则

这五条是后面所有取舍的裁判，冲突时按序号优先。

1. **捕获优先于破解。**
   任何依赖「读取别的 App 私有数据」的路径都是加分项，不是必需项。核心闭环必须只靠系统公开能力（剪贴板、分享、文件系统、MediaStore）就能跑通。

2. **库即文件夹，数据库可抛弃。**
   `blobs/` 里是原始字节，`library.db` 只是索引。删库能重建、能 `git`、能丢进网盘、能用资源管理器看。**不引入任何私有容器格式。**

3. **原始字节只读不改。**
   导入时绝不转码、不压缩、不裁剪。缩略图另存。表情包的灵魂是「原样转发」，一次重编码就可能丢帧、丢透明、变大。

4. **键盘优先，动线最短。**
   高频操作（找图、贴图）不允许出现鼠标。面板打开 → 输入 → 回车，三步结束，中途不弹确认框。

5. **智能功能只做「建议」，不做「决定」。**
   自动分类、自动标签都会给出置信度，默认展示但可一键隐藏/批量纠正。**永远不静默删除、不静默改文件。**

## 3. 用户与场景

只有一个用户：你。所以场景必须抠到具体动作。

### 场景 A · 聊天中的 3 秒（最高频，每天 10–50 次）

> 正在和同事聊需求，想说「这个方案怕是不行」，想发那个扶额的表情。
>
> 手不离键盘：`Ctrl+Alt+Space` → 输 `扶额` → 面板第一张就是 → `Enter` → 微信输入框里已经出现图片 → `Enter` 发送。

**关键要求**：面板 < 200ms 出现；输入即搜；回车后焦点自动回到微信；全程不碰鼠标。

### 场景 B · 周末整理（低频，每月 1–2 次）

> 手机相册 3200 张，想挑出里面的表情包。
>
> 电脑上打开 Picarium → 「相册体检」→ 扫描出 1180 张疑似表情包 → 网格里快速过一遍，剔掉 60 张误判 → 确认 → 手机端把这 1120 张移进 `Pictures/Picarium/` 独立相册 → 相册主视图清净了。

**关键要求**：批量预览要快；误判能一键排除；移动后不影响原 App 使用。

### 场景 C · 从群里收图（每天若干次）

> 群里有人发了个绝妙的表情。
>
> 手机上：长按 → 转发/分享 → 选 Picarium → 入库（自动打上「来自群聊」+ 当天日期）。
> 电脑上：直接 `Ctrl+C` 复制，Picarium 托盘图标闪一下，入库完成。

**关键要求**：零打断，不弹窗，不切 App。

### 场景 D · 迁移 / 备份（一年 1–2 次）

> 换新手机，或者重装系统。
>
> 库在 OneDrive 里，新设备装上 App 指向同一个文件夹，索引重建，一切照旧。

## 6. 标签与分类体系

### 6.1 两类标签，权重不同

| 类型 | 产生方式 | 展示 | 可编辑 |
|---|---|---|---|
| **用户标签** | 手动打 | 永远显示，优先 | 是 |
| **自动标签** | 规则/模型生成 | 默认显示，可全局隐藏 | 可取消、可转为用户标签 |

同一个名字可以同时是两类（例如「猫」自动打了一次，你又手动打了一次），合并展示、双份记录，删除时只删手动那份。

### 6.2 建议的一级标签（首批预置）

```
情感   开心 无语 生气 难过 震惊 害羞 嘲讽 疑问 加油 疲惫
对象   猫 狗 人 动漫 文字图 梗图 表情符号
场景   工作 恋爱 游戏 节日 打招呼 道别
来源   微信 QQ 相册 网页 自制（自动）
系统   未整理 待确认 重复（自动）
```

不做无限层级。需要分组时用「标签组」这种轻量概念，不搞文件夹树。

### 6.3 表情包判别规则（启发式，先跑起来再谈模型）

得分制，`sticker_score ∈ [0,1]`，阈值 0.55 判为表情包：

| 特征 | 加分 | 理由 |
|---|---|---|
| 有 alpha 透明通道（PNG/WebP） | +0.30 | 照片几乎不会 |
| 无 EXIF 拍摄信息（无机型/GPS/拍摄时间） | +0.20 | 表情包是「合成物」 |
| 短边 < 800px 且长边 < 1200px | +0.15 | 表情包普遍小 |
| 文件 < 1.5 MB | +0.10 | |
| 长宽比在 0.5–2.0 | +0.10 | 方形/竖屏居多 |
| 颜色数 < 6 万（量化后） | +0.10 | 卡通/文字图色彩少 |
| OCR 到高置信度文字且文字占比 > 5% | +0.25 | 文字表情包是主流 |
| 路径含 `emoji/sticker/tencent/mm/qq/表情` | +0.30 | 来源强信号 |
| 有相机 EXIF（Make/Model/GPS） | **−0.60** | 强反证 |
| 长边 > 3000px | −0.20 | 照片特征 |

实测目标：**人工抽检 200 张，准确率 ≥ 90%**。达不到就上 CLIP zero-shot 兜底。

## 7. 路线图

### M0 · 技术验证（2–3 天）

**只验证三个「不成就得改架构」的点**，不写产品代码。

| # | 验证项 | 通过标准 | 失败则 |
|---|---|---|---|
| S1 | QQ 明文目录导入 → 哈希 → 缩略图 → 网格显示 | 882 张全部入库，去重正确，< 60 s | 说明路径判断错了，重看目录 |
| S2 | SQLite FTS5 trigram 中文子串搜索 | 「无语」能命中 OCR 文本含「无语」的图；2 字查询可用 | 退回 jieba 分词 + 分词表 |
| S3 | 全局热键 + 无边框置顶面板 + 焦点还原 | 微信里按热键 → 面板出现 → 回车 → 图片进了微信 | 换 Win32 原生窗口或 Tauri |

> 这三项过了，剩下的都是工程量问题；任何一项过不了，架构要改，早改便宜。

### M1 · Windows MVP（2 周）

**验收**：能在真实聊天里用起来，一周内你自己会天天开。

- 库结构与索引流水线
- 导入：拖拽、文件夹、QQ 目录、剪贴板
- 主窗口：网格 + 详情 + 标签 + 搜索
- 快搜面板 + 全局热键 + 复制
- 完全重复去重、回收站
- 库重建、备份导出

### M2 · 智能化（1.5 周）

- OCR 流水线（后台队列，可中断）
- 自动标签：来源、格式、动图、主色、情绪（CLIP）
- 表情包判别 + 「未整理」队列
- pHash 相似聚类 + 合并向导
- 使用统计与「最近使用」

### M3 · Android（2–3 周）

- Capacitor 壳 + 分享接收插件 + 媒体库插件
- 浏览/搜索/收藏/多选/分享
- 相册体检 + 批量移动
- 端侧判别（先用启发式，模型后置）

### M4 · 同步（1 周）

- ops 日志写入/合并
- blob 传输（优先 Syncthing 目录，其次局域网）
- 冲突规则与验证工具
- 双端各 1000 张压测

### M5 · 增强（按需）

- CLIP 语义搜索
- 合集 / 表情包分组
- 微信 `.dat` 解密实验（独立分支，明确标注「随时可能失效」）
- 浏览器扩展「右键收藏」
- 自动粘贴回微信

## 8. 成功指标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 找一张已知表情的中位耗时 | < 8 s（含输入） | 自测 20 次计时 |
