# 26 · 安卓模拟器速查（含「一条命令」与踩坑清单）

> 面向：人和 agent。目标是用**最少 token / 最少试错**把模拟器拉起来、装包、截图。
> 完整构建与签名见 `docs/25-安卓构建、签名与模拟器.md`；这里只讲日常怎么用。

## 1. 一条命令

```powershell
pwsh -NoProfile -File scripts/android-emu.ps1
```

它会：找到 SDK → 有 `emulator-*` 就复用、没有就启动 AVD `Medium_Phone_API_35` → 等 `sys.boot_completed=1` → （可选）装 APK → 拉起 `dev.stickerbox.desktop` → （可选）截图。

常用变体：

```powershell
# 装最新 debug 包 + 截图
pwsh -NoProfile -File scripts/android-emu.ps1 `
  -Apk src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk `
  -Shot .demo/emu.png

# 强制重启（杀掉已有模拟器再起）
pwsh -NoProfile -File scripts/android-emu.ps1 -Fresh

# 换一台 AVD
pwsh -NoProfile -File scripts/android-emu.ps1 -Avd Pixel_4_API_35

# 只起模拟器，不装不拉
pwsh -NoProfile -File scripts/android-emu.ps1 -NoLaunch
```

成功时最后一行是 `OK  serial=emulator-5554  关闭: adb -s emulator-5554 emu kill`。
失败时是 `FAIL: ...`，直接看那行，不用再翻日志。

| 参数 | 默认 | 作用 |
|---|---|---|
| `-Avd` | `Medium_Phone_API_35` | 用哪台 AVD（`emulator -list-avds` 可查） |
| `-Apk` | 空 | 给了就先 `adb install -r`，失败直接退出 |
| `-Shot` | 空 | 截图路径；冷启动后默认等 9 秒再截，避免白屏 |
| `-ShotDelaySec` | `-1`（自动） | 手动指定截图前等待秒数 |
| `-Fresh` | 关 | 先关掉已在跑的模拟器 |
| `-NoLaunch` | 关 | 不拉起 App |
| `-TimeoutSec` | 300 | 等设备和等开机的时间上限 |

## 2. 它背后做的事（想手敲时照这个顺序）

```powershell
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"     # 或你设过就复用
$adb = "$env:ANDROID_HOME\platform-tools\adb.exe"
$emu = "$env:ANDROID_HOME\emulator\emulator.exe"

& $adb devices                                        # 先看有没有 emulator-xxxx  device
Start-Process $emu -ArgumentList "-avd","Medium_Phone_API_35","-no-boot-anim","-gpu","swiftshader_indirect"
& $adb wait-for-device
& $adb shell getprop sys.boot_completed               # 等到 "1"（冷启动 20–40s）
& $adb install -r <apk>
& $adb shell monkey -p dev.stickerbox.desktop -c android.intent.category.LAUNCHER 1
& $adb exec-out screencap -p > .demo/emu.png          # 用 bash 时没问题；PowerShell 下用 Start-Process 重定向
```

**关键顺序**：先确认设备、再等 `boot_completed`，最后才 install / 启动。跳过 `boot_completed` 直接装包，常见结果是 `INSTALL_FAILED_...` 或装完白屏。

## 3. 坑（按出现频率排）

| 坑 | 现象 | 正解 |
|---|---|---|
| `adb` 不在 PATH | `adb: command not found` | 用 `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`，别去改 PATH |
| MSYS/Git Bash 改写路径 | `adb shell ls /sdcard/...` 变成 `C:/Program Files/...` | `export MSYS_NO_PATHCONV=1` |
| PowerShell 调原生命令别设 `Stop` | `npx`/`adb` 往 stderr 写一行 Info，脚本 exit 1 且日志没生成 | `$ErrorActionPreference = "Continue"`，用 `$LASTEXITCODE` 判断 |
| 冷启动白屏 | 截图全白，只有状态栏 | 模拟器 OK 后 App 还要 8–9 秒才渲染；脚本默认等 9 秒 |
| 杀模拟器后立刻起新的 | 新脚本拿着刚死的 serial 白等 5 分钟 | 杀掉后先轮询到 `adb devices` 里没有 `emulator-*`，再启动 |
| 截图是坏的 | PNG 打不开 / 只有几 KB | PowerShell 里不要用 `>` 重定向二进制，用 `Start-Process -RedirectStandardOutput` 或 `adb pull` |
| CDP 连不上 / eval 卡死 | `Runtime.evaluate` 超时 | 页面必须在前台；系统选择器（相册/文件）在前台时一定会挂，先 `adb shell input keyevent 4` 返回 |
| `am start` 模拟分享失败 | `SecurityException: has no access to content://...` | adb 无法伪造 uri 权限，分享入口只能真机或应用内触发 |
| 同一 AVD 已在运行 | `emulator: ERROR: running multiple emulators` | 复用即可（脚本默认复用），或 `-Fresh` |

## 4. 验收标准

- 脚本退出码 0，末行 `OK serial=...`；
- `-Shot` 产出的 PNG **大于 100 KB** 且不是纯白（纯白就是白屏，加大 `-ShotDelaySec`）；
- `adb shell dumpsys window | grep mCurrentFocus` 里出现 `dev.stickerbox.desktop`。

## 5. 换新 AVD / 空库测试

新建的 AVD 是干净系统，App 装上去是**空库**（0 张），正好用来测「导入」和首次启动：

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -list-avds      # 看有哪些
pwsh -NoProfile -File scripts/android-emu.ps1 -Avd Pixel_4_API_35 -Apk <debug apk>
```

- 每台 AVD 的数据各自保留；重开不会丢图，也不会串到别的 AVD。
- 要造测试图：`adb push 图片 /sdcard/Pictures/`，再在 App 里「从系统文件选择器导入」（保留原文件名）或「从手机相册导入」。
- 想清空某台 AVD：`emulator -avd <name> -wipe-data`（会重建 userdata，慢但干净）。

## 6. 为什么不建议让 agent 自己摸

今天实测：让人（或模型）从零摸索「怎么起模拟器」，会依次踩到 adb 路径、MSYS 路径改写、杀进程后 serial 残留、白屏截图这四个坑，单次约 0.3 元。写成脚本后是一条命令、约 40 秒。

所以规则是：**起模拟器只跑 `scripts/android-emu.ps1`，不要临时拼命令**。要改行为就改脚本，改完在这里补一行。
