## 2. 用名规则

- 英文永远写 `Picarium`：首字母大写、不空格、不拆成 “Pica Rium”。
- 中文永远写 `贴屿`：不空格；首次出现可写“贴屿（Picarium）”，之后不要反复括号。
- 新公开材料不再使用 `StickerBox`、`Tietie`、`贴贴`。历史文档可以保留，但要在标题旁标“历史名”。
- 主 tagline 用句点分隔，不用中点：`Together. Instant. Everywhere.`
- `Sticker Hub` 是描述性副标题，不作为商标单独主张。
- 中文对外一句话：**“把散落的贴纸，收在一座小岛上。”**（暂定，可改）

## 3. 品牌层级

```text
Picarium / 贴屿
A cross-platform sticker hub.
Together. Instant. Everywhere.
Collect, organize, search, and share.
```

功能页可用 `Collect · Organize · Paste`；`Together / Instant / Everywhere` 只解释为“收在一起 / 一键调用 / 跨平台”，不要解释成多人协作。

## 6. 分批顺序

1. **第 1 批：用户可见名**  
   改窗口标题、关于页、扩展名/描述、README/新文档；不动 identifier、库路径、自启键、安卓包名。  
   验证：`cargo build -p stickerbox` + `scripts/accept.ps1` + 截图；grep 新公开文案不再出现旧名。

2. **第 2 批：身份与数据迁移**  
   改 identifier、app data、默认库目录、自启键、可执行文件名、Android applicationId。  
   必须带一次性迁移：旧目录存在且新目录不存在时复制/改名；旧自启键删除；失败可回滚。  
   验证：两个临时库 + 旧库副本；切换/重启/自启/卸载重装各一次。

3. **第 3 批：库管理器**  
   多库列表、自定义路径、新建/导入/迁移；全局偏好从 per-library settings 拆出。

4. **第 4 批：发布**  
   NSIS 安装包 + 便携 zip、Android arm64 APK、扩展 zip、README 动态封面、LICENSE/NOTICES、GitHub Releases。
