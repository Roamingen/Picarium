# 09 · 扩展性：插件还是小而美

> 2026-10-28 · 回答「要不要做插件体系」

---

## 1. 结论

**小而美为体，扩展点为用。现在不做通用插件运行时，但把接口留好。**

理由：

| 方案 | 好处 | 代价 |
|---|---|---|
| 纯小而美 | 代码少、bug 少、体验一致 | 你想到的新玩法都得等我写 |
| 通用插件（DLL/WASM） | 理论上无限扩展 | 安全风险、API 一旦改就全废、调试成本翻倍 |
| **预留扩展点（推荐）** | 80% 的自定义需求能用配置解决 | 需要一开始就把数据模型设计对 |

一个个人工具最怕的不是「不够灵活」，而是「插件 API 改了三版，插件全废」。

---

## 2. 四类扩展点（按优先级）

### 2.1 主题（最安全，建议 M1 就做）

```
themes/
  dark.css
  light.css
  我的主题.css
```

CSS 变量已经在用（`--bg/--fg/--accent/...`），只要把 `:root` 抽出来，换一个文件就是换一套皮。
**用户写 CSS，核心零风险。**

### 2.2 规则打标（不写代码的「插件」）

比代码插件实用得多：用户用 JSON 描述规则，核心执行。

```json
{
  "name": "猫猫收集器",
  "version": 1,
  "rules": [
    { "when": { "name_contains": ["猫", "cat"] }, "add_tags": ["猫"] },
    { "when": { "path_contains": ["/表情/"] }, "add_tags": ["表情"] },
    { "when": { "width_lt": 200, "height_lt": 200 }, "add_tags": ["小图"] }
  ]
}
```

放在 `rules/*.json`，导入时自动跑。覆盖了「按来源、按尺寸、按名字」这些最常见的自定义需求。

### 2.3 导入器（M3 后再抽象）

```rust
pub trait Importer {
    fn id(&self) -> &'static str;
    fn detect(&self) -> bool;                 // 这台机器上有没有这个源
    fn scan(&self) -> Result<Vec<ImportItem>>;
}
```

目前导入是「一个文件夹」，等有了剪贴板、手机同步、网盘备份，再抽 trait 也不迟。
**过早抽象 = 猜错接口。**

### 2.4 分类器 / 算法插件（M5，WASM）

```rust
pub trait Classifier {
    fn id(&self) -> &'static str;
    fn version(&self) -> u32;
    fn classify(&self, image: &ImageRef) -> Result<Vec<TagScore>>;
}
```

如果要开放给第三方，用 `wasm32-wasi`：沙箱内运行、不能碰文件系统、接口按 `api_version` 版本化。
**不建议**用动态库（DLL）：一旦加载就是完全信任，出事没法兜底。

---

## 3. 现在就要留好的三个口子（零成本）

| 口子 | 现状 | 要做的事 |
|---|---|---|
| `asset.meta` 自由字段 | 现在有 `tags`，没有通用 meta | M1 加一列 `meta: JSON`，插件/规则想存什么都行，核心不解释 |
| 事件钩子 | 无 | M1 加 `on_import` / `on_index` 两个只读事件，插件可以监听但不能改流程 |
| 规则目录 | 无 | M1 加 `规则/*.json`，先支持 3 种条件（名字/路径/尺寸） |

这三个加上去之后，**80% 的「我想要它自动……」的需求都不用改核心**。

---

## 4. 什么情况才值得上真插件

满足以下三条中的两条：

1. 你自己要写的「功能」已经超过 5 个，且互相独立；
2. 有第三方（朋友）真的想扩展，而不是你自己想象的需求；
3. 数据模型已经稳定 3 个月没改。

否则，**加功能比加插件框架便宜**。

---

## 5. 我的建议

| 阶段 | 做什么 |
|---|---|
| M1 | 主题文件 + `meta` 字段 + 规则打标（JSON） |
| M1.5 | 排序/视图做成配置项（网格密度、排序方式） |
| M3 | 导入器 trait 化（剪贴板、备份、手机） |
| M5 | 如果真有人要写算法插件，再上 WASM + 版本化 API |

一句话：**把「插件」当成一种产品能力，而不是一种技术炫技。**
你现在的自定义需求（改名、标签、悬浮信息、排序）都是核心功能，先做扎实比先做框架值钱。
