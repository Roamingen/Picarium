## 1. 目标与非目标

**目标（本方案覆盖）**

1. 库（数据）与用户配置彻底分开：
   - 库 = `index.json` + `blobs/` + `thumbs/` + `trash/`，可以整体搬走、换盘、放到移动硬盘；
   - 配置 = `settings.json` + `themes/*.json` + 库位置指针，放在系统用户目录，**换库不丢**。
2. PC 设置页能看见当前库与最近库、打开库文件夹、新建 / 打开其他库、搬家（带进度条）。
3. 首次升级时自动把旧布局（配置在库内）迁移到新布局，用户无感。
4. 支持多库：在任意目录新建库、在最近库之间切换；搬库时显示进度条。
5. 测试/开发可以用环境变量完全隔离配置与库，不碰真实用户目录。

**非目标（本方案不做，另行拆批）**

- 安卓库位置（SAF/`content://` 是大工程，单独立项）；
- 便携版"配置也带走"的完整支持（待办 #16，先留环境变量口子）；
- 跨端同步。

## 3. 目标布局

```
%APPDATA%\Picarium\                  ← 全局配置（换库不动）
  config.json                        ← 指针：libraryPath、recent、schema
  settings.json                      ← 全部用户偏好（从库内迁来）
  themes\<id>.json                   ← 自定义主题（从库内迁来）
  settings-export.json               ← 「导出设置」产物（可选，跟随配置目录）

<库根>\                              ← 数据（可搬走）
  index.json
  blobs\ab\cd\<sha>.<ext>
  thumbs\
  trash\
```

- 配置目录默认 `%APPDATA%\Picarium`（用户可见、可手工备份）。
- 环境变量覆盖：`PICARIUM_CONFIG_HOME`（测试/便携/多配置用）。
- 不把配置塞进 `%APPDATA%\dev.picarium.desktop`：那是 Tauri/WebView2 的私有目录，不适合让用户点进去备份。

`config.json` 结构（schema 1）：

```json
{
  "schema": 1,
  "libraryPath": "C:\\Users\\13066\\Picarium",
  "recent": ["C:\\Users\\13066\\Picarium", "D:\\Pictures\\Picarium-2026"]
}
```

- `recent`：最近打开过的库（去重、最新的在前，最多 10 条）；切换/新建后写入；只用于列表和"指针坏了回来找"，**不会**自动打开列表里的库。
- 写入方式：临时文件 + 原子 rename（沿用 `docs/14` §5 的惯例）。

### 3.1 库根解析优先级（新）

1. `PICARIUM_HOME`（开发/测试，行为不变）；
2. `config.json` 的 `libraryPath`；
3. 默认路径 `%USERPROFILE%\Picarium`（旧的 `StickerBox` 改名逻辑保留）。

指针里的路径**不自动回退**到别的库：路径不存在时进"库不可用"流程（批 3 弹窗；批 1 先报错并提示重新选择/用默认库，具体见 §8）。

## 4. 升级迁移（旧布局 → 新布局）

触发：`config.json` 不存在，且能定位到现有库。

步骤（幂等，失败可重试）：

1. 用旧逻辑解析出当前库根（含 `StickerBox`→`Picarium` 改名）。
2. 若库根存在 `settings.json` → **复制**到 `%APPDATA%\Picarium\settings.json`（目标已存在则不覆盖）。
3. 若库根存在 `themes\*.json` → 复制到 `%APPDATA%\Picarium\themes\`（同名不覆盖）。
4. 写 `config.json`（`libraryPath` = 当前库根）。
5. 库里的旧 `settings.json` / `themes/` **保留不删**（旧版本可回退、用户可对照），后续版本再清理；启动日志注明"已迁移"。

失败处理：任何一步失败 → 不写 `config.json`，继续按旧布局运行（设置仍读写库内），并在日志/设置页提示"配置迁移失败"。**不允许"迁移一半后库没指针"导致设置丢失。**

安卓：配置目录用 `app_config_dir()`（app 私有），迁移逻辑可复用；但安卓库位置本批不改。

## 5. 换库流程（批 2，PC 设置页）

### 5.1 交互（多库 + 搬家）

设置 → 「存储」区块：

```
存储
当前库    C:\Users\13066\Picarium        1.6 GB · 882 张
         [打开文件夹] [搬家到其他位置…]

最近库    D:\Pictures\Picarium-2026      [切换]
         C:\Users\13066\Picarium  (当前)

         [新建库…] [打开已有库…]

配置目录  %APPDATA%\Picarium             [打开]
```

- **新建库**：选一个空目录 → 初始化库（`index/blobs/thumbs/trash`）→ 写指针 → 重启。不迁移任何数据，新库从 0 张开始；旧库原样保留（用户随时切回）。
- **打开已有库**：选含 `index.json` 的目录 → 写指针 + 写入 `recent` → 重启。
- **切换最近库**：同上，只写指针，不动任何文件。
- **搬家**（批 3）：把当前库整体移动到新位置，带进度条；完成后指针指向新位置并重启。
- 切换/新建/搬家后统一弹「需要重启才能生效」：[立即重启]（`app.restart()`）[稍后]。
- 「更换位置…」弹目录选择（`tauri-plugin-dialog` 已装，`src-tauri/Cargo.toml:18`）→ 选中后校验：

| 目标状态 | 处理 |
|---|---|
| 不存在 / 空目录 | 允许「新建库」/ 搬家目标 |
| 已有库（含 `index.json`） | 允许：切换到这个库（不走搬家） |
| 是当前库 / 在当前库内部 | 拒绝 |
| 无写权限 / 盘符不存在 | 拒绝并说明 |
| 目标所在盘剩余空间 < 库大小 | 拒绝（批 3 做精确估算） |

### 5.2 搬家（换位置）

> 多库切换 / 新建库只写指针、不复制文件（§5.1）；只有「搬家」走下面流程。

对话框二选一（默认值：同盘「移动」，跨盘「复制后切换」）：

- **移动**：同盘 `rename`（瞬时）；跨盘 = 复制 + 校验 + 删旧（删旧前必须指针已切换成功）。
- **复制一份**（勾选「保留原库」）：复制 + 校验 + 切指针，旧库原样保留。

执行顺序（安全不变式：**指针永远指向一份完整的库**）：

1. 停写：暂停导入/剪贴板监听，等待进行中的写完成（`Mutex<Library>` 已有）。
2. 目标落盘：复制 `blobs/ thumbs/ trash/ index.json`，逐文件计数 + 总字节校验（批 3 加 sha 抽样/全量）。
3. 校验通过后，写 `config.json`（原子 rename）。
4. 才执行"移动"的删旧。
5. 提示"需要重启生效"，[立即重启] [稍后]。

失败：指针不动，回滚 = 删掉目标半成品（或保留供排查），旧库继续用。

### 5.3 为什么重启生效

运行期换库要处理：所有 WebView 的缓存状态、`AppState.lib` 的 Arc 换新、热键/剪贴板监听重挂、窗口几何。重启是零风险路径；"热切换"收益小、坑多，本批不做。

## 8. 边界场景与处理

| 场景 | 处理 |
|---|---|
| 升级用户（旧布局） | §4 自动迁移；旧文件保留 |
| `config.json` 有路径但目录不存在（移动硬盘没插） | 批 1：启动报错并提示设 `PICARIUM_HOME` 或改 `config.json`；批 3：弹窗「重试 / 选择其他库 / 用默认库」 |
| 用户手工删 `%APPDATA%\Picarium` | 配置回到默认；库位置回退默认路径；库数据不受影响 |
| 目标目录非空但无 `index.json` | 拒绝，提示「选择空目录」 |
| 目标在现库内 / 反向 | 拒绝（防止把自己搬进自己） |
| 迁移中断电 | 指针未写 → 重启仍用旧库；目标目录是半成品，提示清理 |
| 旧版本程序回退 | 旧版本读库内 `settings.json`（迁移时保留）；库位置退回 `%USERPROFILE%\Picarium` |
| 双实例 | 现有单实例锁（127.0.0.1:47821）沿用；迁移时加"库正被占用"检查 |
| 便携版 | 本批：配置仍在 `%APPDATA%`；批 16 再讨论"便携=配置跟 exe 走" |
| 安卓 | 不改；配置目录用 app 私有目录，库位置仍 app 私有 |

## 10. 拍板结果（2026-11-21）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 配置目录位置 | `%APPDATA%\Picarium`（默认即可）；`PICARIUM_CONFIG_HOME` 可覆盖；便携版延迟 #16 |
