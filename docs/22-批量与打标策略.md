# 22 · 批量处理与打标策略（设计草案）

> 2026-10-31 · 只是设计，不写代码；等有真实需求再落地

---

## 1. 结论

不做插件运行时（WASM/DLL/Lua），分两层：

1. **声明式规则（JSON）**：覆盖 90% 的「按名字/来源/尺寸/格式自动打标、归组」；
2. **外部策略进程**：用户用自己的语言写脚本，app 通过 stdin/stdout 交换 JSON。

这样「用户提供策略」不需要我们把运行时、沙箱、调试器都背进来，也不会因为第三方代码崩溃拖垮主程序。

## 2. 为什么不做内嵌脚本

| 方案 | 问题 |
|---|---|
| WASM 插件 | 要引入 wasmtime、定 ABI、做权限模型；用户还得装 Rust/C 工具链 |
| Lua/Rhai | 运行时小，但仍要沙箱、超时、错误隔离；生态和调试都弱 |
| DLL | 仅 Windows，崩溃直接带走主进程 |
| WebView 里跑 JS | 能力受限、拿不到可靠文件系统，安全边界也差 |

外部进程天然隔离：崩了是子进程崩，超时直接 kill，用户想用 Python/Node/Go 都行。

## 3. 第一层：声明式规则

存放：库根目录 `rules/*.json`（可多个文件、可导入导出）。

```json
{
  "id": "wechat-clip",
  "name": "微信剪贴板自动归组",
  "when": {
    "all": [
      { "field": "source", "op": "eq", "value": "clipboard" },
      { "field": "source_ref", "op": "contains", "value": "Weixin" }
    ]
  },
  "then": [
    { "add_tag": "微信" },
    { "add_group": "表情" }
  ]
}
```

支持的字段：`name`、`ext`、`bytes`、`width`、`height`、`source`、`source_ref`、`added_at`、`tags`、`groups`。
操作符：`eq / contains / starts_with / regex / gt / lt / in`。
动作：`add_tag`、`add_group`、`rename`（模板）、`star`。

规则可设置触发时机：

- `on_import`：导入后自动跑（异步，失败只记日志）；
- `manual`：只在批量栏「策略」里手动跑。

## 4. 第二层：外部策略进程

配置：设置 → 策略 → 新增外部策略。

```json
{
  "id": "my-tagger",
  "name": "我的打标脚本",
  "command": ["python", "C:/scripts/tagger.py"],
  "timeout_ms": 10000,
  "mode": "batch"
}
```

调用协议（`api: 1`）：

**stdin**

```json
{
  "api": 1,
  "library": "C:/Users/13066/Picarium",
  "assets": [
    {
      "sha": "ab12…",
      "name": "蓝色大肥鱼_跳舞",
      "path": "C:/Users/13066/Picarium/blobs/ab/12/ab12….gif",
      "ext": "gif",
      "bytes": 3153920,
      "width": 500,
      "height": 500,
      "tags": ["图片"],
      "groups": ["蓝色大肥鱼"],
      "source": "clipboard",
      "source_ref": "Weixin.exe",
      "added_at": "2026-08-18T14:07:42+08:00"
    }
  ]
}
```

**stdout**

```json
{
  "api": 1,
  "actions": [
    {
      "sha": "ab12…",
      "add_tags": ["微信"],
      "add_groups": ["表情"],
      "rename": "蓝色大肥鱼_跳舞",
      "star": true
    }
  ]
}
```

约束：

- 只允许改元数据（标签/分组/名字/收藏）；删除、覆盖文件、移动 blob 一律拒绝；
- 未知 sha、超长标签、非法分组名直接丢弃并在结果里报告；
- 进程超时 kill，输出上限 10MB；
- 不经过 shell（`Command::new` + args 数组），避免注入；
- 批量调用一次传全部选中项，不做逐张进程启动。

## 5. 批量 UI

批量栏新增「策略」按钮：

```
[已选 12 张] [全选] [策略…] [加入分组] [加标签] [复制文件] [收藏] [删除] [取消]
```

流程：**选策略 → 预览 → 应用 → 可撤销**。

- 预览显示「将影响 N 张，新增标签 3 个，移动分组 1 个」，并列出前几条 diff；
- 应用前把 `index.json` 快照到 `backups/index-<时间>.json`；
- 批量栏出现「撤销本次」按钮，恢复快照（只回滚索引，不动文件）。

## 6. 打标的想法

1. **来源驱动**：剪贴板来自微信 → 「微信」；来自 Snipaste → 黑名单默认不收，收了的也可打「截图」；
2. **名字规则**：`^蓝色大肥鱼` → 分组「蓝色大肥鱼」；含「红包」→ 标签「红包」；
3. **尺寸/格式**：宽 ≤ 1000 且 GIF → 标签「微信可发」；
4. **时间**：本月导入 → 标签「2026-10」；
5. **外部模型**：想要 CLIP/本地小模型，就写进外部策略，app 不管模型依赖。

不做内置 AI 打标：模型体积、显卡依赖、误标成本都不适合塞进主程序。

## 7. 工作量

| 阶段 | 内容 | 估计 |
|---|---|---|
| P2-1 | 规则 JSON + 匹配引擎 + 预览/应用/撤销 | 1.5–2 天 |
| P2-2 | 外部进程适配（协议、超时、校验） | 1 天 |
| P2-3 | 设置页管理策略 + 导入导出 | 0.5–1 天 |
| 可选 | `on_import` 自动跑规则 | 0.5 天 |

## 8. 不做

- 插件市场 / 在线分发；
- 脚本里删除文件、转换格式、写回原图；
- 移动端跑外部进程（安卓只保留声明式规则）。
