## 6. 已知坑（会重复踩的）

- **`ops_edit_file` 保留 mtime**：等长替换（如 `0.18.1` → `0.19.0`）后 Git/cargo 可能认为没改；本次 Cargo.toml/tauri.conf/AGENTS 就因此对 Git 隐形，必须 `touch`。改 Rust/版本文件后若 `git status` 不显示，先 touch 再查。
- **设置分页映射**：新增 `.set-row` 必须在 `SETTING_TAB_BY_LABEL` 里登记，否则默认 `general`，在「外观」页永远不显示。这是本次「还是没有」的根因。
- **版本号不等于构建号**：版本号是手写的，不会每次编译自动变；10b/10j 做完后没升号，所以 `cargo run`/release 都显示 0.18.1。功能落地后按 `AGENTS.md` §10 升号，别再让用户用版本号猜构建。
- **运行中的 debug exe 锁文件**：`cargo build -p picarium` 会报 `failed to remove ...\target\debug\picarium.exe: 拒绝访问 (os error 5)`；先关 App。`accept.ps1` 开头会强杀 picarium，跑前要告知用户。
- **git push 的 SSH 代理**：本机 7897 未监听时，`git push` 报 `FATAL: Unable to connect to relay host, errno=10061`；本次用 `GIT_SSH_COMMAND='ssh -o ProxyCommand=none' git push origin main` 直连成功。不要改 `~/.ssh/config`，也不要把代理写死。
- **单实例锁** `127.0.0.1:47821`：旧实例开着时新实例会静默退出；`cargo run` 前先关旧窗口。
- **MSYS 路径**：`PICARIUM_HOME`/`PICARIUM_CONFIG_HOME` 必须传 Windows 绝对路径（`C:/...`）；传 `/c/...` 会污染真实库。
- **`window.setSize` 权限**：Tauri JS 窗口尺寸 API 可能被权限拒绝；测试用应用自己的 `invoke('set_window_size')`。
- **mock CRLF**：`docs/mock/panel-v2.html`、`desktop-main-v4.html` 是 CRLF；`ops_edit_file` 的 oldText 要按 CRLF 写，否则找不到。
- **用户真实库**：不要碰 `C:\Users\13066\Picarium` 和 `D:/test/pic`；测试只用 `PICARIUM_HOME` 临时库。
