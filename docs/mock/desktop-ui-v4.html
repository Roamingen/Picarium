为什么这样排：菜单头三项是「拿到这张图」的三个动作（编辑 / 复制图片 / 复制文件），也是使用频率最高的一组； 中间是状态（收藏）；下半是归类（加入标签 / 加入分组，点开就是悬浮面板，所以不留 › 子菜单箭头）； 危险动作单独一段、红字沉底。不提供「在文件夹中显示」——那是内部 blob 路径，不给用户看见。
交互约定：单击 = 复制（带 260ms 防抖）；双击 = 编辑（第二次 click 会取消待执行的复制，不会写剪贴板）； 右键 = 菜单，并把键位表里 mouse3 从「编辑」解绑，否则右键永远只会开编辑、菜单永远出不来。
多选时：右键只弹「批量项」（复制文件 / 收藏 / 删除 / 加入标签 / 加入分组），不弹单图项。

旧面板的问题：416px 高的一列输入框，五组之间只有 6px 间距，视觉上糊成一片；格式是五个复选框、来源是弹层、预设是复选框，三套控件三种手感； 顶部没有「现在到底筛了什么」的反馈，只能数格子。
改法：分组卡片化（每组一条 1px 分隔 + 组标题，右侧一句「留空表示不限」这类说明）； 格式/标签统一成可点 chip（带全库计数，点了才知道会剩多少）；来源改分段控件；预设改成可叠加的虚线 chip； 顶部显示「3 项生效」，底部显示「筛选结果 132 张」，应用前就知道会剩下多少。
实现落点（给下一批用）：
· 卡片交互：src-tauri/ui/app.js 卡片上新增 dblclick → openEditor(a)；contextmenu 里去掉 keymap 分流，改调新的 openCardMenu(a, x, y)；键位表 edit 的 mouse3 解绑。
· 标签管理：#tagmanage 的 .tm-modal 宽度改 470，行内按钮默认 opacity: 0、.tm-row:hover 时 1；行内编辑沿用现有 tmEditing 状态机，只换渲染。
· 筛选面板：index.html 的 #filter-panel 整块重写（仍是固定面板，不改弹出方式）；app.js 的 fillFilterPanel/readFilterPanel 跟着换控件类型；style.css 里 .fp-* 整段替换。
