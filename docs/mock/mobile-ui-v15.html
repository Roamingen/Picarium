两区规则与落地方案

先把「置顶顺序」和「分组顺序」分开存，拖拽就不会互相踩。

① 置顶区内拖

只换置顶顺序 → set_pinned_groups(newPinnedOrder)。置顶组之间的顺序就是 S.pinned 数组顺序，group_order 不动。

② 未置顶区内拖

只换未置顶顺序 → set_group_order([...newPinnedOrder, ...newUnpinnedOrder])。core 会把没提到的组补在后面，所以这里必须传完整顺序。

③ 跨区与收藏夹

拖到分区边界就夹紧，不改变置顶状态；要置顶/取消置顶仍然走多选底栏。收藏夹固定最上，不参与拖拽，也不在多选里。

为什么现在拖了没效果
  • .folder 没有 touch-action:none，长按后一拖，浏览器先判定为滚动 → pointercancel；pointermove 里的 preventDefault() 拦不住原生滚动（mobile.js:1450-1460）。
  • 落点用 S.groupList 的顺序算（mobile.js:912），但渲染按 pinned-first 重排（mobile.js:334-348），落点会跳。
  • renderFolders() 每移动一次就重建 DOM（mobile.js:918），setPointerCapture 丢，拖动中断。
  • pointercancel 只 clearTimeout + resetHold（mobile.js:1465），不清 dragCtx/ghost，卡片残留。
修法
  • 拖动期间给 #folders 加 touch-action:none; overscroll-behavior:contain，或非 passive touchmove 在 armed 后 preventDefault()。
  • 用一份 renderedOrder（pinned-first）算落点，不要用 S.groupList。
  • FLIP 只改 transform，不重建 DOM；松手再 set_group_order / set_pinned_groups。
  • pointercancel 走 endFolderDrag()，清 ghost、恢复滚动。
