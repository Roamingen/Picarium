交互规则

01 输入搜索框兼新建没有 + 按钮；输入即过滤分组。
→
02 无同名出现新建行列表顶部虚线行，「回车」也可触发。
→
03 建组立即选中清空搜索，回填该分组，footer 变成「加入「xxx」」。
→
04 加入仍走现有确认再点 footer 才真正写库，避免误建即加入。

和标签面板的差异：标签是本地多选、底部一次提交；分组是单选目标，所以新建后直接选中，不进入“待建区”。

边界

  • 搜索为空 → 全部分组，不出现新建行。
  • 有同名分组（忽略大小写）→ 直接显示并选中已有分组，不重复建。
  • 空白名字 → 不建，保留输入；创建失败 → toast，不关面板。
  • 搜索命中任意分组 → 不显示新建行；无命中且有输入才显示。
  • 新建后立刻点「加入」是两步；如果只想建组不加图，可点 × 关闭，分组已保留。

实现备注

  • mobile.html：删 #pick-new 与 #pick-newrow，搜索 placeholder 改「搜索或新建分组」。
  • mobile.js：renderPicker() 里算 exact 与 showCreate，生成横跨两列的 .pickcreate；createPickGroup(name) 接收参数，成功后 loadGroups()、pickSel=name、清空 pq、重渲染。
  • 事件：#pq 输入时重渲染；新建行点击 / 搜索框 Enter 触发；去掉 setPickNewMode 与 + 按钮监听。
  • mobile.css：删 .newbtn / .newrow 旧样式，加 .pickcreate；其余沿用 .pick / .folders / .folder。
  • 不改 create_group 命令；沿用现有 pickSel 单选与 footer 提交逻辑。

没做 / 下一步

  • 批量新建（一次输入多个名字）。
  • 新建后自动加入（不做，保留确认）。
  • 分组重命名 / 合并 / 删除（另一条管理链路）。

本批只统一“新建分组”的入口习惯，不碰分组管理。
