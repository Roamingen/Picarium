安卓字体设置 Android

把 PC 上的 Zed 式字体设置搬到手机：界面 / 列表与卡片 / 详情与浮层三档可以各自选西文、中文、回退链和字号。安卓 WebView 不能枚举系统字体，所以来源只有系统通用族和用户导入的字体文件；Nerd Font 也必须导入。

系统通用族 + 导入 3 个作用范围 Nerd Font 只接管 PUA 不改卡片 / 控件高度 PC 端 mock →
01

先选来源，再选字体

系统只暴露 sans-serif / serif / monospace / sans-serif-condensed 四个通用族；要固定中文字形或图标，必须导入字体文件。

02

西文、中文、回退分开

每个作用范围都有独立的 Latin、CJK 和回退链；列表 / 详情默认跟随界面，关掉跟随才单独覆盖。

03

字体只影响文字

卡片、网格、按钮和底部选择器的高度不变；字号上限建议 18，先在小屏和长文件名下验收。

!
平台边界（先说明）：安卓 WebView 没有 queryLocalFonts 一类的枚举能力，也不会暴露“微软雅黑 / 思源黑体”这样的系统家族名。本稿只列 4 个通用族 + 导入文件；列表里预置的三个“导入”字体是演示数据，真实导入流程在底部选择器里。

实现备注

确认后的实现批，不是 mock 表面

字体栈：西文 → 中文 → 回退 → NF

每个作用范围生成一条 CSS 字体栈；顺序是 Latin、CJK、回退链，最后才是只覆盖 PUA 的 Nerd Font 符号槽。系统兜底永远放在最后。

font-family:
  var(--latin),
  var(--cjk),
  var(--fallback-1),
  "SB Nerd Symbols",
  sans-serif;

Nerd Font 必须导入

安卓没有可用的系统 NF 字体。导入后用 FontFace 或本地文件协议加载，再创建 unicode-range 只覆盖图标区的符号槽；这样 NF 的等宽 Latin 不会抢正文。

new FontFace("SB Nerd Symbols",
  "url(asset:///fonts/nf.ttf)", {
    unicodeRange:
      "U+E000-F8FF, U+F0000-FFFFD"
  });

导入流程：先读 cmap，再分角色

ttf-parser 读 family 与 cmap：是否含中文、是否等宽、是否含 PUA，决定列表里的「中文 / 等宽 / NF」徽标。TTC 只取第一个字面；导入文件复制到 App 私有目录，卸载时一起删除。

WebView 不能枚举，所以「刷新系统字体」这个动作不存在；只能刷新导入列表。

持久化与验收

设置写进 settings.json 的 fonts 段，和 PC 同一结构，安卓只多 imported 文件清单。主窗 / 浮层启动时都要能读到。

验收在 12 / 14 / 16 / 18 四档、长英文名、中文、NF 图标下看：列表标题截断、选择器行不撑高、底部 sheet 不遮住确认按钮、无横向溢出。

需要你拍板

  1. 作用范围 3 档够不够？现在分 界面 / 列表与卡片 / 详情与浮层；要不要再把输入框、标签编辑器单独拆一档？
  2. 安卓字体来源选 A. 系统通用族 + 用户导入（本稿，0 包体）、B. 内置 1–2 款开源字体（+1–3MB，开箱即用）、还是 C. 只跟系统？
  3. Nerd Font 默认开还是关？本稿默认开，演示字体是已导入的 JetBrainsMono NF。
  4. 字号上限 18 还是 20？本稿滑杆到 20，备注建议 18 以内；手机小屏更容易裁切。
  5. 是否需要“每个作用范围单独设行高 / 字重”？本稿有，但只做了字号、行高、字重三项；字距和 OpenType 特性先不放到手机端。
