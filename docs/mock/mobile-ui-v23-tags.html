为什么这么设计

  • 一个面板，两个入口。图库多选和分组内多选的底栏本来就有「标签」，两处打开同一个面板；scope 统一显示「已选 N 张」，分组名在背景里已经看得见，不再重复。
  • 先选后提交。点标签先本地选中，底部「添加 N 个标签」一次提交；和「添加到」同一节奏，多选场景少写盘、少 toast，误触还能再点一下取消。
  • 搜索框兼新建。输入不存在的名字，列表上方出现「新建标签「xxx」」，点一下进待新建区，回车同效；trim 后和现有标签同名时不重复建，直接选中已有。
  • 数字用全库数量（沿用筛选面板）；所选的图全都有这个标签时显示「✓ 已加」并禁用，避免无效点击。
  • 应用后关面板 + toast「已为 5 张添加 2 个标签」，保持多选；失败时 toast 原因，面板不关、已选不清空。
  • 键盘弹起时底栏保持可见（不套用全局 body.kbd .ffoot 的隐藏规则），列表区压缩滚动。

需要你拍板

  1. 确认式（现在这版）还是点一下立即生效？建议确认式，和「添加到」一致。
  2. 数字用全库总数，还是「已选里已有几张」（如 3/5）？现在用全库总数。
  3. 应用成功后要不要自动退出多选？现在保持选中。
