标签 chip · 移除模式

中性＝没选；红底「−」＝将移除；黄字＝只有部分选中图有它（移除只影响那几张）。

底部按钮

0 选中 → 置灰；两种模式按钮颜色不同，红＝破坏性操作。

文案

已为 5 张移除 2 个标签

和添加的「已为 N 张添加 X 个标签」同一句式，只有动词不同。

为什么不是底栏再加一个按钮

底栏已经 5 个（发送 / 标签 / 添加到 / 存相册 / 删除），再加「移标签」会挤到一屏放不下，而且它和「标签」共用搜索、共用列表、共用提交，本质是同一个面板的两个方向。

为什么默认「添加」

整理时加多于减；移除是纠正错误，是低频动作。默认停在移除会让人误以为系统只想让你删东西。

为什么移除模式不显示「新建」

移掉一个还不存在的标签没有意义；搜索框只做过滤，不出现「新建标签」行。

和单图编辑的关系

单图详情点「+ 标签」进的编辑模式本来就能点 × 移出这张图；这里补的是多选批量移除——现在多选只能加不能减。

数据与命令（零 Rust 改动）

  • 命令已经存在且是批量的：remove_tags { shas, tags }（src-tauri/src/commands.rs:440），内部走 lib.remove_tags(&shas, &tags)。
  • chip 右边的 N/M 由前端算：遍历选中的 a.tags 数出现次数，不发请求；同时它有值就说明「至少有 1 张带它」，天然过滤掉无关标签。
  • 提交后照现有习惯刷新 tag_stats，并本地回写 a.tags（参照 applyTags 添加分支 mobile.js:3767-3780）。

前端落点

  • openTagSheet(shas, {mode}) 增加 remove；toggleTag 分支；applyTags 走 remove_tags。
  • mobile.html 的 #tagsheet 里加 .modesw 分段控件（标签管理入口 #tag-manage 保持不动）。
  • mobile.css 加 .modesw / .tg.rm / .tg.part / .selchip.rm / .apply.danger。

文案口径

  • 完成：已为 5 张移除 2 个标签（对应添加的 已为 5 张添加 2 个标签）。
  • 说明行：移除只是把标签从这几张图上去掉，标签本身和它的其它图片不受影响——这是用户最容易误解的一点。
  • 空态：这 2 张还没有标签 + 一键切到「添加」。

实现顺序建议

  1. 先加分段控件 + 移除列表（只读），确认计数 5/5、3/5 对得上；
  2. 再接提交与本地回写，最后补空态与 toast。
