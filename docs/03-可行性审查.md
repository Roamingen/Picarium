> 结论先行：**Conditional Go（有条件可行）** —— 主链路成立，微信批量导入这条腿断掉，但产品不缺这条腿也能跑。

## 1. 结论

| 判断 | 内容 |
|---|---|
| **技术上能不能做** | 能。核心闭环（导入 → 分类 → 搜索 → 粘贴到微信/QQ → 手机同步）全部基于系统公开能力，已在本机验证关键环节。 |
| **要花多久** | 全职约 **46 人日**；兼职（每周 8–10 小时）约 **5–6 个月**。只做 MVP（M0+M1）是 **13 人日**，兼职 3–4 周。 |
| **最大不确定性** | ① 微信 1464 张存量无法批量导入（需人工/剪贴板慢慢收）；② Android WebView 网格性能；③ HyperOS 后台限制。 |
| **最大风险** | 不是技术，是**范围膨胀**。这个题目太容易做成「什么都要有」的巨型工具。 |
| **要不要做** | 要。现有工具最多覆盖 50–70%，缺的正是「跨软件粘贴 + 跨端同步 + 表情包判别」这三块。 |

## 4. 必须做的三个试验（M0）

每个试验都有明确的「失败即改架构」判据，时间盒严格执行。

### S1 · QQ 导入端到端（0.5 天）

```
目标：882 个文件 → 库 → 网格可见
步骤：扫描目录 → SHA-256 → 落 blobs → Pillow 读宽高 → 生成 512 WebP → 写 DB → 静态页渲染网格
通过：882/882 入库；重复文件只留一份；总耗时 < 60 s；缩略图无破损
失败：说明路径/权限判断有误，重新勘察
```

### S2 · 中文全文检索（0.5 天）

```
目标：5000 条合成数据，验证 FTS5 + jieba 的中文召回
步骤：造 5000 条 OCR 文本（含「我真的无语了」「猫猫叹气」等）→ jieba 分词写入 FTS5 → 查询
通过：「无语」召回正确；「猫」召回正确；P95 延迟 < 20 ms；2 字查询有结果
失败：退到 `tokenize='trigram'`，或全表 LIKE + 倒排缓存
```

### S3 · 热键面板贴回微信（1 天）

```
目标：在微信 4.1 里完成「热键 → 搜索 → 回车 → 图片出现在输入框」
步骤：RegisterHotKey → 无边框置顶窗口 → 搜索框 → 选中写 CF_DIB → 还原焦点 → 人工 Ctrl+V
通过：连续 20 次，20 次成功；唤起 < 200 ms；焦点还原成功率 ≥ 90%
失败：换 Win32 原生窗口，或退化为「复制后手动 Ctrl+V」（仍然可用，只是慢 1 秒）
```

> 这三项加起来 2 天，能挡掉 80% 的「做到一半发现路不通」。

## 6. 现有方案对比（为什么不自建不行）

| 方案 | 覆盖度 | 缺什么 | 成本 |
|---|---|---|---|

## 8. 什么情况下我会建议你「别做」

诚实地说，有三种情况应该停手：

1. **你其实只需要「快贴」**——那用 uTools 的剪贴板历史 + 一个文件夹 + 系统搜索就够了，投入 46 人日不值。
2. **你三个月内不会天天用**——这类工具的价值来自高频；低频的话，一个整理好的文件夹 + 标签命名就够了。
3. **你更想练手而不是解决问题**——那就换个明确的练手项目，别用「我的表情包」当借口，容易做成半成品。

反过来，如果你符合下面三条，那就值得做：

- 每天聊天超过 1 小时，且经常发表情；
- 存量确实上千张，翻相册找图已经是真实痛点；
- 愿意接受「第一批 1000 张要花一个晚上整理」的冷启动成本。

## 9. M1 结束时的验收 Demo

我会给你演示这 6 个动作，全部通过才算 M1 完成：

1. 指向 QQ 目录 → 一句命令导入 882 张 → 网格出现，耗时 < 60 s。
2. 搜「猫」→ 出图 < 100 ms；搜「无语」→ 命中 OCR 文本。
3. `Ctrl+C` 复制任意图片 → 托盘闪一下 → 库里多一张，自动标「剪贴板」。
4. 在微信里 `Ctrl+Alt+Space` → 输两个字 → 回车 → 图片进输入框。
5. 批量选中 20 张 → 打标签「工作」→ 侧栏计数 +20。
6. 删掉 `library.db` → 重启 → 索引自动重建，标签和使用记录不丢（来自 ops）。

第 6 条是整套架构的「体检」：**如果删库能重建，说明数据真的是文件，不是数据库的囚徒。**
